# Parity notes (Go)

- The API has **no job progress route** (`POST /jobs/{id}/progress` was always 404). `Jobs().UpdateProgress` and `JobContext.Progress` return `*resources.UnsupportedError` (matches `ErrUnsupported`) without a network call; `EventJobProgress` is never emitted.
- `POST /webhooks/{org_id}/custom` returns `{ job_id, queue_name, status }` (OpenAPI `WebhookResponse`). `Ingest().Custom` / `CustomWithToken` map that; empty 200 leaves the fields unset. The route always requires the org webhook token (`X-Webhook-Token`): `Custom` takes it from `CustomWebhookRequest.WebhookToken` and returns `ErrWebhookTokenRequired` without a request when it is empty. There is no `/webhooks/{org_id}/github` or `/stripe`: `Ingest().GitHub/Stripe` return `ErrUnsupported`.
- Worker list has a summary-specific `ListSummaries()` API; legacy `List()` maps summaries into `Worker` values for compatibility. Both shapes carry `jobs_processed` / `jobs_failed` (0.1.122).
- `lease_id` is required on REST complete/fail/heartbeat (422 `VALIDATION_ERROR` without it, 0.1.121) and on gRPC complete/fail/renew (`InvalidArgument`, 0.1.100). REST request fields stay `*string` for compatibility; the docs say required.
- `GET /jobs` and `GET /jobs/dlq` take `status` (comma list), `q`, `job_type`, `created_after`, `created_before` (RFC 3339; bad values 400), `order_by`, `order_dir`, and send `X-Has-More`; `GET /jobs/{id}/history` (`order_dir`, alias `order`) sends it too. `ListPage` / `History` read the header (`Base.getPage`).
- Outgoing webhooks carry `format` (`json` default, `slack`, `discord`, `teams`); events add `job.deadlettered`, `job.retried`, `workflow.completed`, `workflow.failed`. Enum-like fields are Go string types, so unknown values decode as their names.
- `GET /webhooks/deliveries` is the inbound webhook log (no payload): `Ingest().ListDeliveries`. Unrestricted keys only.
- `X-RateLimit-Limit/-Remaining/-Reset` (Unix seconds) and `X-RateLimit-Scope` are sent on every authenticated response; the SDK reads them into `RateLimitError` on a 429.
- Full gRPC streams.
- Zero-value gRPC fields are a footgun; document for callers.
- gRPC enqueue: `MaxRetries`/`TimeoutSeconds` are `*int32` (nil = server defaults).
- Workflow job list/get/status are not their own REST routes. `GET /workflows/{id}` carries jobs + dependencies; `Jobs().ListJobs` reads that document. Its job rows have no `key` (only `POST /workflows` returns `job_ids` key mappings), so `WorkflowJob.Key` is empty; `CreateWorkflowResponse.ApplyKeys` / `KeyByJobID` map keys, as in Node/Python. `POST /jobs/{id}/dependencies` takes `depends_on` + `dependency_mode` and returns `dependencies_added` / `dependencies_met`.
- `GET /workflows/{id}` is `WorkflowDetailResponse`: job counts are under `progress` (`total`/`completed`/`failed`), not top-level `total_jobs` like list/cancel/retry. `Workflow.UnmarshalJSON` maps those onto `TotalJobs`/`CompletedJobs`/`FailedJobs`.
- `GET /jobs/{id}/dependencies` is `{ job_id, dependencies, dependents, dependencies_met }` with `{ job_id, queue_name, status }` edges, not a nested `job` object or string id lists.
- Email availability is `GET /auth/check-email?email=`, not `POST /auth/email/check`. The body is `available`, `exists`, `signup_enabled`.
- Email login start is `POST /auth/email/start` → `{ message, email_sent_to }`, not `{ success, message }`.
- `POST /auth/email/verify` is tagged `{type: login, access_token, ...}` or `{type: signup, signup_token, email, expires_in}`. `Auth().VerifyEmail` maps both; login-only fields dropped `signup_token`.
- `POST /auth/validate` is `{ valid, error?, claims? }`. Claims are `org_id`, `api_key_id`, `queues`, `exp`. `ValidateResponse.UnmarshalJSON` maps those onto `OrganizationID` / `APIKeyID` / `Queues` / `ExpiresAt`.
- `POST /auth/logout` blacklists the access token from `Authorization`. The refresh JWT stays usable until expiry unless `refresh_token` is in the body. `Auth().Logout` sends the stored refresh token (or an explicit argument).
- Org webhook token is `GET/POST /organizations/webhook-token` (auth-scoped), not `/organizations/{id}/webhook-token`. `POST .../webhook-token/clear` exists but always answers 422 (clearing is not allowed), so `ClearWebhookToken` returns `ErrUnsupported`; rotate with `RegenerateWebhookToken`.
- Org usage is `GET /organizations/usage` (auth-scoped), not `/organizations/{id}/usage`.
- Admin org update is `PATCH /admin/organizations/{id}`, not PUT. Hard delete is `?hard_delete=true`, not `?hard=true`.
- `GET /admin/stats` is nested `{ organizations, jobs, workers, system }`, not flat `total_organizations` / `total_jobs`.
- `GET /admin/plans` is a flat `PlanLimits` array (`tier`, `display_name`, limit fields on the same object), not `{ limits, price, description }`.
- Slug check is `GET /organizations/check-slug?slug=`, not `/organizations/check-slug/{slug}`. Body is `available`, `valid`, `error`, `suggestion`.
- Job list/DLQ summaries send `attempt` and `max_retries`, not `retry_count`. `Jobs().List` maps `attempt` onto `Job.RetryCount`. Detail `GET /jobs/{id}` still uses `retry_count`.
- Job `payload` / `result` / `tags` is `serde_json::Value`, not only objects. `map[string]any` failed to unmarshal string/array/bool JSON.
- Schedule `payload_template` / `tags` / `metadata` is `serde_json::Value`. `map[string]any` failed to unmarshal string/array/bool JSON.
- `GET /jobs` summaries include `job_type` from `payload.job_type`. `Job.JobType` maps that field; GET detail copies it from `payload` when the top-level field is absent.
- `GET /jobs/status` returns `{ id, status, queue_name, retry_count, created_at, completed_at }` (no `attempt`/`max_retries`). `BatchStatus` maps `retry_count` onto `RetryCount`.
- `POST /schedules` returns `{ id, name, cron_expression, next_run_at }`, not a full `Schedule`. `Schedules().Create` backfills queue/timezone/payload from the request and sets `IsActive` true (the insert is always active).
- Queue config upsert is `PUT /queues/{name}/config`. `GET`/`DELETE /queues/{name}` exist; PUT on that path is 405.
- Prometheus scrape is `GET /metrics` (text, no `/api/v1` prefix). There is no JSON `/api/v1/metrics` or `/api/v1/metrics/prometheus`.
- `avg_processing_time_ms` (queue stats) and `avg_wait_time_ms` / `avg_processing_time_ms` (dashboard) are `f64` on the wire: `*float64`, never `*int`. Backend f64 fields: `models/queue_config.rs:143`, `api/handlers/health.rs:112`, workflow `progress_percent`, usage `percentage`.
- `GET /schedules` honors only `limit` (default 100, max 500). `Schedules().List` sends only `limit` (500 when a client-side filter is set) and applies `QueueName` / `IsActive` / `Offset` locally. `GET /outgoing-webhooks/{id}/deliveries` takes no query at all (newest 100); `Deliveries` filters `Status` / `Offset` / `Limit` locally. `UpdateScheduleRequest.QueueName` is ignored by the API.
- 429 has two kinds. `RATE_LIMIT_EXCEEDED` (Retry-After header) is retried. `QUOTA_EXCEEDED` (`{error:"limit_exceeded", resource, current, limit, plan, upgrade_to}`, no Retry-After) is a plan limit: `RateLimitError.Quota != nil`, `IsRetryable()` false, not counted by the circuit breaker. 408 is retryable; other 4xx never are.
- Acks (job `complete` / `fail` / `heartbeat`, worker `heartbeat`) go through `Base.PostAck`: idempotent retry + `SkipCircuitBreaker`. A repeat after a lost response gets 409 `CONFLICT` "Job is already <status>", which the worker treats as success (`isAlreadySettled`). `POST /jobs/{id}/fail` rejects an empty or over-2048-character `error` with 400, so `FailWithResponse` runs `CoerceFailureMessage` (empty -> "Job failed", truncate to 2048 characters on a rune boundary).
- Job `payload` / `result` numbers decode as `float64` unless an integer exceeds 2^53, which stays a `json.Number` (`resources/numbers.go`: `decodeResponse` normalises through a tree, `restoreNumbers` fixes `any` slots). Custom `UnmarshalJSON` on `Job` / `Workflow` must use `unmarshalJSON`, not `json.Unmarshal`. gRPC `Struct` numbers are doubles, so IDs above 2^53 lose precision over gRPC.
- gRPC: TLS default is port 443 (or no port) only; `localhost:50051` is plaintext. `spooled.Config.GRPC` / `WithGRPCTLS` / `WithGRPCOptions` reach `grpc.ClientOptions`. `toStruct` JSON-round-trips payload/result into `structpb`, and an unencodable value is returned as an error. `FailRequest.retry` is `optional bool` on the backend (absent = retry per `max_retries`, false = dead-letter now). The SDK proto deliberately keeps a plain `bool retry` so `pb.FailRequest.Retry` stays a `bool` (source compatible); it is the one line `scripts/generate_grpc.sh` rewrites and `TestProto_MatchesBackendProto` accepts (`sdkProtoOverrides`). `Fail` always sends retry explicitly: `true` as the field, `false` for `NoRetry` via `grpc.SetNoRetry`, which appends field 4 = 0 to the message's unknown fields (wire `20 00`; the backend reads Some(false)). A plain proto3 `false` is never put on the wire, which is why `NoRetry` did not dead-letter in 1.4.0; `ProcessJobs` users call `SetNoRetry` themselves. `FailRequest.Retry` (SDK struct) is deprecated and ignored. `FailWithResponse` returns `will_retry` / `next_retry_delay_secs`. `RegisterWorkerRequest.WorkerID` maps to `optional string worker_id`.
- Realtime: reconnect is on unless `DisableAutoReconnect`; the server ends every SSE/WS stream after 30 minutes. Read limit `MaxMessageBytes` (default 4 MiB) for both SSE (`bufio.Scanner.Buffer`) and WebSocket (`SetReadLimit`). SSE sends the credential as `Authorization: Bearer` only (the backend still accepts `?api_key=`). `job.status_changed` data is `old_status` / `new_status` (no `status`); `JobEvent.Status` is filled from `new_status`. `job.completed` `result` may be any JSON (`JobEvent.RawResult`; `Result` only for objects). The WebSocket client keeps its own login-JWT cache and never touches the REST transport's auth.
